# Physical Gate v0.5 candidate — authority continuity and route closure

**Status:** implementation candidate. Validation deferred.

v0.5 is additive: existing v0.4 classes remain unchanged.

## Added properties

- signed root authority profile with optional bounded budgets;
- ordered delegation chains with parent digests;
- signer-to-principal key binding;
- monotonic attenuation of operations, time, target, exact bindings, and bounded budgets;
- execution-time revalidation of the complete authority chain;
- exact tool-contract commitments;
- route commitments binding gate, executor, entrypoint, action, and tool contract;
- route closure/enforcement evidence digests;
- execution receipt bindings for root authority, delegation chain, tool contract, and route proof.

## Key invariants

1. A child delegation may preserve or reduce authority, never expand it.
2. A trusted signing key may sign only for the principal to which it is externally bound.
3. Authority must still be valid at the moment of execution.
4. The tool contract approved by the gate must match the contract presented at execution.
5. The execution route must match the approved gate/executor/entrypoint commitment.
6. Route closure is not inferred from an `exclusive=true` flag alone; closure and enforcement evidence are separately bound.
7. State freshness and monotonic state lineage remain required.
8. Existing replay reservation still occurs before the simulated external effect.

## Important route-closure limitation

The route proof is a signed commitment to deployment evidence. It is not a network/topology scanner and cannot independently prove that no hidden bypass exists.

A production deployment must establish the closure/enforcement evidence through a sufficiently independent configuration or attestation path.

## Performance/storage intent

The new checks are digest- and metadata-oriented and add no persistent cache. Delegation and route artifacts can be content-addressed and represented by digests in downstream receipts.
